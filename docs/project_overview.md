# captureAIshi — 项目说明

> 面向投资人 / 项目经理的非技术概览。读完本文可以向他人完整介绍这个项目。

---

## 一句话定义

**captureAIshi 是一套针对已上市 3A 游戏的自动化相机数据采集系统。**
它能在不修改游戏文件、不需要游戏源代码的前提下，接管游戏内的相机，
沿预设路径自动拍摄数百到数千帧 RGB 图像 + 深度图 + 法线图，
生成用于训练 AI 视觉模型的高质量真实游戏场景数据集。

---

## 解决什么问题

### 背景

训练图像 AI（深度估计、3D 重建、场景理解、NeRF、高斯泼溅）需要大量
**带有精确摄像机姿态（位置+角度）和深度标注的图像数据**。

现有数据来源的痛点：

| 数据来源 | 问题 |
|---------|------|
| 合成引擎（Unity/UE 自建场景）| 美术资产质量低，不像真实游戏画面 |
| 真实世界采集 | 深度标注昂贵，相机姿态不精确 |
| 公开游戏截图 | 无相机姿态，无深度，无法用于有监督训练 |
| 商业游戏官方 API | 绝大多数游戏不提供 |

**captureAIshi 的解法**：直接接管已上市游戏的相机，用程序全自动控制视角，
同时导出每一帧对应的精确相机内外参、像素级深度图和法线图。
游戏场景本身就是数百名美术花数年打磨的高质量 3D 内容，数据质量远超合成场景。

---

## 核心能力

### 1. 无源码相机劫持（核心技术壁垒）

通过 **DLL 注入 + 内存逆向**，在运行时找到游戏内相机对象的内存地址，
直接写入自定义的位置、角度、视野角（FOV）。
游戏引擎正常渲染，但相机完全听从外部指令。

支持引擎：Unreal Engine 3 / 4 / 5（包含 UE5 大世界坐标 LWC）、
REDengine 4（赛博朋克）。

已验证游戏：Batman: Arkham Knight、Hellblade、《黑神话：悟空》（测试中）、
Cyberpunk 2077（测试中）。

### 2. 相机路径自动化播放

用户定义相机路径（轨道环绕、螺旋上升、直线扫描、8字形等），
系统以 60 帧/秒高精度播放，确保路径覆盖均匀、没有人手抖动误差。

路径可在 Web UI 中可视化预览（3D 视图），确认后一键执行。

### 3. RenderDoc 帧数据导出

配合开源工具 **RenderDoc**，每一帧都能导出：
- **RGB 图像**：游戏最终渲染画面
- **深度图**（像素级，与 RGB 精确对齐）
- **法线图**（表面朝向，用于几何理解）
- **相机内参**（焦距、视野角）和**外参**（世界坐标系位置+旋转）

所有数据以标准格式写入 `trajectory.json`，可直接喂给 NeRF、3DGS、
深度估计等训练框架。

### 4. Web 操作界面

无需命令行。操作员通过浏览器界面：
- 选择目标游戏（内置 6 款游戏配置文件，可扩展）
- 设计相机路径
- 一键采集
- 实时查看采集进度和图像预览

## 技术路线（简版）

```
游戏进程
    ↑ DLL 注入 (bridge.dll)
    |   └─ TCP 9998 接收相机指令
    |
captureAIshi Python 主程序
    ├─ 相机路径计算（Catmull-Rom 曲线平滑）
    ├─ 指令发送（60Hz 精度写入游戏内存）
    └─ RenderDoc 触发每帧数据导出
         └─ RGB + Depth + Normal → output/<session>/
```

**注入侧（C++）**：扫描游戏内存，定位 GEngine → CameraManager → 相机 POV 地址，
以 1000Hz 频率写入目标相机姿态。AOB 特征码匹配，无需逐版本适配。

**控制侧（Python）**：生成路径 → 发指令 → 收数据 → 打包输出。
全程自动化，支持定时任务批量采集。

## 团队与开发方式

本项目采用 **多 AI Agent 并行开发**：
- **主程序员（老白）**：架构决策、代码审查、跨模块协调
- **小逆**：游戏逆向、DLL 注入、内存协议、Windows 底层
- **小由**：Web UI、用户体验、前端可视化
- **小萱**：RenderDoc 渲染管线、深度/法线数据导出

每个 Agent 专注自己的模块，通过共享文档协作，由人类负责最终决策。
